# Supabase / PostgreSQL
#
# Added by the Render deployment phase. Nothing above this line changed, and a
# resolve of the line below moves none of the pins above it -- same discipline
# as the SCOUT block, and verified the same way, with `pip install --dry-run`.
#
# This is additive in the strong sense: SQLite is NOT removed. It still backs
# Chroma's store and SCOUT's langgraph checkpointer, neither of which Supabase
# replaces, and it stays the local development database. Postgres is selected at
# runtime by DATABASE_URL being set -- unset, the app behaves exactly as it does
# today, and this dependency is never imported.
# ==============================================================================

# psycopg 3. Not psycopg2, and not asyncpg. Both extras are required rather
# than convenient:
#
#   [binary]  Ships libpq compiled into the wheel. This is the difference
#             between deploying and not deploying: Render's native Python
#             runtime gives no apt, so there is no libpq-dev on the box to
#             build against. Plain `psycopg` falls back to a source build and
#             fails the build step. (The same is true of psycopg2 without the
#             -binary package, which is the usual version of this mistake.)
#
#   [pool]    SQLiteManager._get_connection opens and closes a connection on
#             every single call. Against a local file that is free. Against
#             Supabase each one is a TCP handshake plus a TLS handshake across
#             the network, and this process runs the auction's seven-second bid
#             timers on the same event loop -- so per-call connections turn
#             every query into tens of milliseconds the clock does not have.
#             psycopg_pool keeps a small set open and hands them out.
#
# psycopg 3 serves the sync and the async API from one package, so this pin does
# not commit us on whether PostgresManager blocks or awaits -- that choice is
# made in the manager, not here.
#
# Note: db/check_supabase.py's install hint still names 3.2.3, from when that
# script was written. It is only printed when psycopg is missing entirely, but
# it now disagrees with this pin and should be corrected.
psycopg[binary,pool]==3.3.6
